# ADR-004 — Modalidad de Mercado Pago, webhooks y conciliación

- Estado: accepted
- Aprobación humana: 2026-07-23, con PoC Sandbox de webhooks, conciliación e idempotencia antes de aprobar la especificación
- Fecha: 2026-07-21
- Decisores: usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: RF-01, feat-007

## Contexto

El MVP cobra una tarifa fija. La acreditación debe provenir del proveedor, resistir reintentos y poder conciliarse; el retorno del navegador no prueba un pago.

## Drivers de decisión

- Menor superficie PCI y fraude.
- Implementación rápida del camino feliz.
- Idempotencia, auditoría y conciliación.
- Evolución posterior a pagos embebidos sin contaminar el dominio.

## Opciones consideradas

1. Checkout API/Bricks embebido: mejor continuidad visual, mayor integración.
2. Checkout Pro con redirección: experiencia preconstruida y menor superficie inicial.

## Decisión

Usar Checkout Pro en el MVP. La API crea una intención local y una preferencia con referencia externa e idempotencia; el cliente redirige al proveedor. Un webhook HTTPS valida firma, registra el evento bruto sin datos sensibles, consulta la API de Mercado Pago y aplica idempotentemente la transición. Solo `approved` confirmado por servidor produce `PAYMENT_CONFIRMED`. Ejecutar conciliación periódica de intenciones pendientes y reporte de diferencias. No guardar tarjetas ni tratar la URL de retorno como confirmación.

## Consecuencias positivas

- Menor complejidad de checkout y exposición de datos de tarjeta.
- Fuente de verdad y auditoría explícitas.
- Checkout API puede agregarse detrás del mismo puerto de pagos.

## Costes y riesgos

- Redirección fuera de PIGAR.
- Webhooks duplicados, tardíos o fuera de orden requieren diseño cuidadoso.
- Reembolsos, contracargos, señas y split payments quedan fuera del primer release.

## Estrategia de salida o reversión

El dominio usa `PaymentIntent` y un puerto de proveedor. Checkout API u otro proveedor podrá añadirse con un adaptador y migración de flujo.

## Evidencia/PoC requerida

- Sandbox: aprobado, rechazado, pendiente, duplicado y fuera de orden.
- Pérdida del webhook recuperada por conciliación.
- Prueba de firma inválida, replay e idempotencia concurrente.
