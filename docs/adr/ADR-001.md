# ADR-001 — Monorepo y stack web para cliente/backoffice

- Estado: accepted
- Aprobación humana: 2026-07-23, con las condiciones de `docs/architecture-review.md`
- Fecha: 2026-07-21
- Decisores: usuario (alcance), usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: feat-001, feat-002, feat-004

## Contexto

El MVP tendrá únicamente un portal mobile-first para clientes y un backoffice para administración. No habrá aplicación ni portal de operarios; administración cargará la asignación y los hitos operativos.

## Drivers de decisión

- Dos experiencias web con contratos y componentes compartidos.
- TypeScript estricto de extremo a extremo.
- Despliegue sencillo en un único VPS.
- Mantener abierta una futura aplicación de operarios sin pagar su coste ahora.

## Opciones consideradas

1. Una sola aplicación con áreas por rol: despliegue simple, mayor acoplamiento de UX y permisos.
2. Dos aplicaciones Next.js dentro de un monorepo: límites claros y reutilización controlada.
3. Cliente web y aplicaciones nativas: fuera del alcance definido.

## Decisión

Adoptar la opción 2. Usar pnpm workspaces y Turborepo; `apps/customer-web` y `apps/admin-web` con Next.js; paquetes compartidos para contratos, dominio sin framework, diseño, configuración y utilidades. El portal cliente será responsive e instalable como PWA, pero no dependerá de instalación ni de capacidades offline.

## Consecuencias positivas

- Menor superficie y coste que la propuesta anterior.
- Separación clara entre experiencia pública y administrativa.
- Una futura app de operarios puede consumir la misma API.

## Costes y riesgos

- Se mantienen dos aplicaciones web.
- Los paquetes compartidos necesitan límites para no acoplar ambas interfaces.
- No hay captura directa de hitos por parte del técnico en el MVP.

## Estrategia de salida o reversión

La API y los contratos no dependen de Next.js. Las aplicaciones pueden unificarse o incorporarse una app móvil más adelante mediante un nuevo ADR.

## Evidencia/PoC requerida

- Build y despliegue de ambas aplicaciones en el VPS.
- Verificación responsive del flujo crítico del cliente y permisos administrativos.
