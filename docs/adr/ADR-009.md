# ADR-009 — Imágenes inmutables de staging en GHCR

- Estado: accepted
- Aprobación humana: 2026-07-25
- Fecha: 2026-07-25
- Decisores: usuario, Leader y Architect Reviewer (recomendación)
- Relacionado con: feat-012, REQ-012-001 y REQ-012-002

## Contexto

Hostinger Docker Manager interpreta un Compose desde URL y administra sus
variables después de crear el proyecto. Durante una actualización no construye
los servicios definidos con `build:`; intenta iniciar imágenes ya disponibles.

## Drivers de decisión

- Despliegue manual repetible en staging.
- No compilar código de aplicación en el VPS.
- No almacenar credenciales de GitHub en Hostinger.
- Conservar trazabilidad exacta entre revisión validada e imagen ejecutada.

## Opciones consideradas

1. Construir manualmente las imágenes en el VPS.
2. Mantener `build:` y depender del comportamiento del Docker Manager.
3. Publicar imágenes OCI inmutables en GHCR después de calidad exitosa.

## Decisión

Adoptar la opción 3 exclusivamente para staging. El workflow publica
`pigar-app` y `pigar-nginx` en GHCR bajo el SHA completo de la revisión que
superó calidad. Docker Manager descarga esas imágenes públicas durante una
actualización manual. No se configura despliegue automático ni acceso de
GitHub al VPS.

## Consecuencias positivas

- Hostinger no necesita compilar y cada actualización apunta a una revisión
  verificable.
- No se transfieren secretos de staging a GitHub Actions.
- El rollback consiste en seleccionar un SHA de imagen anterior validado.

## Costes y riesgos

- Se debe confirmar que ambos paquetes de GHCR sean públicos para permitir el
  pull anónimo desde Hostinger.
- La publicación de imágenes agrega consumo de GitHub Actions y almacenamiento
  de paquetes.

## Estrategia de salida o reversión

Se puede volver a construir en otra plataforma OCI o cambiar el `image:` del
Compose sin afectar los volúmenes de staging. La reversión inmediata selecciona
un SHA de imagen anterior validado.

## Evidencia/PoC requerida

- Workflow de publicación exitoso para ambas imágenes.
- Confirmación de visibilidad pública y pull anónimo desde Hostinger.
- Actualización manual del proyecto seguida de smoke tests sanitizados.
