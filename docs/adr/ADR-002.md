# ADR-002 — Backend, base de datos y despliegue en VPS

- Estado: accepted
- Aprobación humana: 2026-07-23, con las condiciones de `docs/architecture-review.md`
- Fecha: 2026-07-21
- Decisores: usuario (Hostinger), usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: feat-001 y todas las features de dominio

## Contexto

El usuario definió un VPS de Hostinger para backend, backoffice y multimedia. El backend seguirá siendo autoridad de permisos, pagos y transiciones y necesita persistencia transaccional, webhooks y jobs.

## Drivers de decisión

- Aprovechar el VPS ya elegido.
- Despliegue repetible y recuperable.
- Consistencia transaccional y auditoría.
- Operación viable para un equipo pequeño.

## Opciones consideradas

1. Servicios instalados directamente en el host.
2. Monolito modular y servicios aislados con Docker Compose.
3. Plataforma cloud administrada: descartada para el MVP por la restricción elegida.

## Decisión

Adoptar la opción 2. API REST/OpenAPI en NestJS sobre Fastify, PostgreSQL con Prisma y un worker del mismo código. Ejecutar contenedores separados para Nginx, aplicaciones web, API, worker y PostgreSQL mediante Docker Compose versionado. Usar volúmenes separados para base y multimedia, red interna para servicios no públicos, healthchecks, límites de recursos y secretos fuera del repositorio. Nginx será el único ingreso HTTP/HTTPS y entregará archivos privados únicamente después de autorización interna de la API. No introducir Redis inicialmente; usar outbox transaccional y jobs reclamados desde PostgreSQL.

## Consecuencias positivas

- Entorno reproducible y servicios aislados dentro del VPS.
- Una transacción puede abarcar agregado, historial y outbox.
- Contenedores OCI y PostgreSQL conservan portabilidad.

## Costes y riesgos

- VPS, base y multimedia comparten CPU, disco y dominio de falla.
- El equipo es responsable de parches, firewall, backups, monitoreo y recuperación.
- Un despliegue o disco defectuoso puede afectar todo el sistema.

## Estrategia de salida o reversión

Contenedores, PostgreSQL y un adaptador neutral de archivos permiten separar cada servicio o migrar de hosting. No depender del filesystem efímero de los contenedores.

## Evidencia/PoC requerida

- Despliegue reproducible desde un VPS limpio.
- Backup cifrado fuera del VPS y restauración probada de PostgreSQL y del volumen multimedia.
- Prueba de límites de disco, reinicio, TLS, firewall y rollback/forward-fix.
