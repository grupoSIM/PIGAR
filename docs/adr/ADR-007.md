# ADR-007 — Estado in-app y canales externos diferidos

- Estado: accepted
- Aprobación humana: 2026-07-23; el MVP ofrece estado e historial dentro del portal, sin chat ni mensajería integrada
- Fecha: 2026-07-21
- Decisores: usuario (alcance), usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: RF-05, feat-009

## Contexto

El MVP no tiene aplicación de operarios. El cliente necesita conocer la asignación y, opcionalmente, el hito `EN_CAMINO`, pero no se definió un proveedor externo de push, email o WhatsApp.

## Drivers de decisión

- No incorporar proveedores sin aprobación.
- Mostrar siempre el estado persistido y vigente.
- Mantener una ruta clara para alertas futuras.

## Opciones consideradas

1. Estado solo dentro del portal.
2. Email transaccional.
3. Push/WhatsApp multicanal.

## Decisión

Usar la opción 1 para el MVP. El portal consulta la API y muestra el estado actual, historial visible y hora de actualización. Toda comunicación ofrecida por PIGAR ocurre entre cliente y administración; no se muestran enlaces de llamada o WhatsApp del técnico. Administración coordina con el técnico por WhatsApp fuera del sistema, sin integración, almacenamiento ni auditoría en PIGAR. El dominio mantiene un outbox de eventos para poder agregar canales después, pero ningún worker envía mensajes externos. Email, Web Push y WhatsApp integrados requieren un ADR complementario o revisión de este ADR con proveedor, consentimiento, plantillas, costes y soporte aprobados.

## Consecuencias positivas

- Sin dependencia ni coste de mensajería en el MVP.
- No se confunde una alerta con la fuente de verdad.
- Evolución futura sin cambiar eventos de dominio.

## Costes y riesgos

- El cliente debe entrar al portal para ver cambios.
- No hay aviso proactivo de asignación o salida.

## Estrategia de salida o reversión

El outbox y el contrato neutral de eventos permiten conectar adaptadores de email, Web Push o WhatsApp.

## Evidencia/PoC requerida

- Actualización consistente de estado e historial tras refrescar o reanudar sesión.
- Verificar que el portal nunca presenta ubicación exacta o una estimación en tiempo real del técnico.
