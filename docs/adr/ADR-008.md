# ADR-008 — MVP online y estrategia offline diferida

- Estado: accepted
- Aprobación humana: 2026-07-23, con las condiciones de `docs/architecture-review.md`
- Fecha: 2026-07-21
- Decisores: usuario (sin app de operarios), usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: feat-004, feat-006

## Contexto

La necesidad offline original provenía principalmente del trabajo de campo. Al quedar la aplicación de operarios fuera del MVP, cliente y administración pueden requerir conexión para operaciones de negocio.

## Drivers de decisión

- Reducir estados y conflictos innecesarios.
- Mantener pagos y transiciones bajo validación inmediata del servidor.
- No almacenar datos sensibles de forma persistente en navegadores compartidos.

## Opciones consideradas

1. Aplicaciones web online con borradores locales mínimos.
2. PWA offline-first con sincronización completa.
3. Cola offline para operarios: fuera del alcance actual.

## Decisión

Adoptar la opción 1. Solicitudes, asignaciones, transiciones, conformidad y pagos requieren conexión y confirmación del servidor. El portal cliente puede conservar temporalmente un borrador no sensible en memoria o almacenamiento local con expiración; domicilio, tokens y multimedia no se cachean de manera persistente por defecto. Reintentos HTTP usan claves idempotentes donde una duplicación tenga impacto. La estrategia offline de operarios se decidirá cuando feat-006 vuelva a alcance.

## Consecuencias positivas

- Menor complejidad y menor exposición local de datos.
- No existen conflictos diferidos en estados ni dinero.
- Idempotencia sigue protegiendo doble envío y reintentos.

## Costes y riesgos

- Una pérdida de conectividad interrumpe el flujo.
- Un formulario puede requerir reingreso si no es seguro persistirlo.

## Estrategia de salida o reversión

Los comandos de API conservarán IDs idempotentes y versiones de agregado, base útil para una futura cola offline.

## Evidencia/PoC requerida

- Doble envío, timeout y reintento de creación/pago.
- Verificar limpieza de borradores y ausencia de domicilio, tokens o multimedia en caches persistentes.
