# ADR-006 — Multimedia privada en el filesystem del VPS

- Estado: accepted
- Aprobación humana: 2026-07-23; límites técnicos y retención permanecen sujetos a PoC y validación legal
- Fecha: 2026-07-21
- Decisores: usuario (VPS Hostinger), usuario (aprobación), Leader y Architect Reviewer (recomendación)
- Relacionado con: RF-03, feat-004, feat-010

## Contexto

El usuario definió que videos e imágenes se almacenarán en el mismo VPS de Hostinger que ejecuta backend y backoffice. Los archivos son sensibles y pueden llegar desde conexiones móviles inestables. Agregar un object store autocontenido introduce coste operativo/licenciamiento sin aportar redundancia en un único host.

## Drivers de decisión

- Cumplir la restricción de infraestructura sin sumar otro producto.
- Mantener archivos privados y fuera del filesystem efímero de la aplicación.
- Evitar buffering completo en memoria.
- Controlar capacidad, integridad, acceso y retención.

## Opciones consideradas

1. Volumen privado del VPS con adaptador de almacenamiento.
2. Object store autocontenido en el mismo VPS: más complejidad sin eliminar el punto único de falla.
3. Object storage externo: descartado como almacenamiento primario por decisión de alcance.

## Decisión

Usar la opción 1. Montar un volumen/directorio persistente dedicado, fuera de las imágenes de contenedor y no servido públicamente. La API autoriza y recibe la carga por streaming hacia un archivo temporal, aplica límites de tamaño/MIME, calcula checksum y realiza rename atómico al completar. Nombres físicos aleatorios; metadatos y relación con la solicitud en PostgreSQL. Para descarga, la API autoriza actor y propósito y delega el archivo a Nginx mediante redirección interna; nunca expone la ruta física. Esta es una excepción explícita a la preferencia por carga directa firmada porque el almacenamiento primario elegido es filesystem local. Cada solicitud admite hasta cinco imágenes opcionales y un video opcional de máximo 30 segundos. Los límites técnicos iniciales propuestos son 10 MB por imagen y 50 MB para el video, sujetos a PoC. Retención propuesta: 180 días después del cierre, pendiente de validación legal.

## Consecuencias positivas

- Cumple el hosting elegido con pocas piezas operativas.
- La API no carga el archivo entero en memoria y Nginx sirve descargas eficientemente.
- El adaptador permite migrar a object storage más adelante.

## Costes y riesgos

- Reanudar una carga exige reiniciar el archivo completo en el MVP.
- Aplicación y multimedia compiten por disco/ancho de banda en el VPS.
- Sin backup externo, una pérdida del VPS sería irrecuperable.

## Estrategia de salida o reversión

El dominio guarda un descriptor neutral. Un job puede copiar archivos a storage S3-compatible y cambiar el adaptador sin alterar órdenes ni URLs públicas.

## Evidencia/PoC requerida

- Carga móvil interrumpida/reintentada, MIME/tamaño inválido, checksum erróneo y acceso cruzado.
- Verificar streaming con memoria acotada, archivos temporales huérfanos, alerta de disco y limpieza por retención.
- Backup externo cifrado y restauración completa probada.
